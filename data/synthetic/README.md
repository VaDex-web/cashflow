# data/synthetic — синтетические выписки для демо и тестов

Основной вход — реальный датасет организаторов в `data/raw/` (его генератор не трогает).
Синтетика нужна для демо-сценария с заложенным кассовым разрывом и для тестов `api/`,
где реальных данных нет. Формат — **как у датасета** (`docs/contract.md`, п. 1.1): UTF-8 с BOM, `;`,
`company_id; operation_id; operation_date; amount; direction (Поступление/Списание); counterparty_inn; counterparty_name; payment_purpose; balance_eod`.

```bash
python data/synthetic/generate.py                    # всё заново (детерминированно, seed=7)
python data/synthetic/generate.py --format internal  # внутренний формат п. 1.2 (date, amount, direction in/out, …)
python data/synthetic/generate.py --end 2026-09-30   # другая дата последней операции
```

Во всех: зарплата 2 раза в месяц (аванс и расчёт, перенос на предыдущий рабочий день), аренда, коммунальные,
ЕНП до 28-го (НДФЛ и взносы, авансы УСН 28.04/28.07/28.10, годовой УСН, НДС тремя частями после квартала,
налог на прибыль), операции только в рабочие дни по производственному календарю РФ 2024–2026.
«Грязь» как в реальной выписке: дубли строк, пустые назначения и ИНН, 7 написаний ЕНП, переводы собственных
средств в другой банк и обратно, возвраты ошибочных платежей, пропуски нескольких дней выгрузки (S01, S04), овердрафт.

## Файлы

| путь | что |
|---|---|
| `statements/S0x.csv` | выписки (загружать в сервис) |
| `companies.csv` | справочник в формате `data/raw/companies.csv` |
| `future/S0x.csv` | «как было на самом деле» 45 дней после последней операции — только для проверки прогноза |
| `integrations/S0x/1c_export.json` | выгрузка учётной системы: счета покупателям и от поставщиков, договоры с графиком, зарплатные ведомости |
| `integrations/S0x/bank.json` | данные банка: графики кредитов, ведомости зарплатного проекта, созданные/подписанные платёжные поручения |
| `integrations/S0x/registry.json` | открытые реестры: статус контрагентов, банкротство, долги по налогам, арбитраж, ФССП; госконтракты |
| `integrations/S0x/contracts.json`, `invoices.csv` | договоры и счета в формате загрузки `api/` (`POST /companies/{id}/integrations/contracts/upload`) |
| `demo_scenario.md` | демо-сценарий и его JSON-описание |

Данные источников согласованы с выпиской и с `future/`: счёт, который «пришёл» в будущем, есть в 1С как открытый,
ведомость зарплатного проекта совпадает с будущим списанием и т.д. Все компании, люди и ИНН вымышлены.
